## 실패 원인과 수정

[상세 원인 분석](FAILURE-ANALYSIS.md)에 사실과 가설을 분리했다.

- 초기 인증 거절은 Responses Write 부족이었다. 저장 뒤의 간헐 거절은 서버 권한 판정에서 발생했으나, 당시 요청 ID가 없어 인증 캐시 전파가 내부 원인인지는 확정하지 못했다. 추가 권한 확대나 새 키 없이 현재 정상화됐고, 기본 SDK에서도 확인했다.
- 초기 화자 오류는 현재 사용자의 보고와 상대의 직접 진술을 혼동한 계약 해석 문제였다. 개인 Claim의 화자 의미를 명확히 했다.
- 기존 평가기는 모든 기능을 불완전한 개인 대화1턴에 의존했다. personal/flow/joint 입력을 분리하고 실제 승인 카드·일정·기억 상태·역할 변형 fixture를 제공했다.
- 개발 실험에서 날짜만 있는 요청을 자정으로 보충해 START_IN_PAST가 발생했다. 공통 규칙으로 시각 미정은 null을 유지하도록 수정했고, 원본·수정안 모두 재검증했다.

검증을 완화하거나 사례별 응답·특정 문장 분기를 넣지 않았다. 실제 모델 실패를 테스트 응답으로 대체하지 않았다.
