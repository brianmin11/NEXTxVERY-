# 통합 구현 범위와 실행

통합 브랜치 `codex/relationship-integration`은 앱 `민경민@ef47b6a` 기반이며 AI `1e204e9`의 소스·검사·연결 문서를 `packages/relationship-ai`에 가져왔다. 다른 개발자의 브랜치와 AI 원본 브랜치는 수정하지 않는다.

## 실행

Node24.15 이상. `npm ci`, `npm run build:engine`. `.env.example`을 참고해 gitignored `.env.local`에 임의의 긴 인증 secret과 로컬 base URL을 설정한다. `npm run local`로 localhost3111에서 시작한다. 모델 키는 서버 환경에만 넣는다. 기존 키 파일을 사용할 때는 `OPENAI_KEY_ENV_FILE=/absolute/path/.env.local npm run local`처럼 프로세스에 경로를 전달하며 파일을 복사하지 않는다.

서로 다른 브라우저 프로필/비공개 창에서 `/login`의 계정 만들기를 사용한다. 첫 계정이 더보기에서 가족 공간을 만들고 초대 코드를 두 번째 계정에게 전달한다. 두 번째 계정은 자기 계정으로 로그인해 초대 코드로 참가한다. 일정 탭에서 실제 저장할 일정을 만든 후 홈의 마음 전하기에서 시작한다.

## 실제 경계

- Better Auth의 이메일/암호 로그인·서버 세션, Node SQLite 영속 파일을 사용한다. 계정 전환 흉내나 브라우저 저장소만 사용하는 데모가 아니다. 이번 로컬 시험 계정은 합성 계정이다.
- SQLite는 로컬 통합용이다. Vercel 런타임에서는 시작을 거부한다. 공개 배포 전 외부 영속 DB/저장소 어댑터와 인증 운영 설정·마이그레이션을 구성하고 재검증해야 한다. Supabase RLS를 구현/검증했다고 주장하지 않는다.
- 개인 원문은 소유자만 받으며 공동 응답은 승인된 카드와 파생 결과만 포함한다. UI 숨김 대신 서버 조회·명령에서 권한을 검사한다.
- 첫 실행 종류는 **기존 일정 한 건의 일회성 변경**이다. AI 초안 전체를 자동 실행하지 않으며 실제 반영할 제목·시각·참여자를 별도 폼에서 확인하고 같은 버전의 전원 수락을 받는다. 반복/가사/외부 알림 자동 실행은 후속 범위다.
- 테스트 모델은 호스트 단위 테스트에서 의존성 주입한다. 앱 서버는 live 또는 unconfigured만 제공하며 실제 모델 오류를 테스트 문구로 대체하지 않는다.
- 현재 개인 입력은 현재 작업에 명시적으로 제공한 내용만 사용한다. 장기 기억 자동 회상·개인 이력 삭제 관리·상품 월 요금제는 이번 연결 범위 밖이다.

## 실패 원인과 수정

공동 초안 두 차례가 의미 검증에서 거절됐다. 첫 실패는 원출력을 보관하지 않아 세부 원인을 확정하지 않는다. 두 번째를 합성 조율 ID에만 제한한 임시 진단으로 확인한 결과, 모델이 서버 발급 합의 ID 대신 조율 ID를 반환했고 자연어 시각에서 변환한 ISO 값을 원문에 그대로 있는 sourced 값으로 표시했다. 누락된 담당자는 미정 상태로 유지하는 것이 맞다.

서버가 발급한 ID·revision·draft 상태를 호출별 출력 스키마에 고정하고, 정규화한 시각은 정확한 원문 문자열 근거가 없으면 proposed 및 확인 필요 필드로 표시하도록 공통 프롬프트를 수정했다. 이름·날짜·특정 사례별 분기를 추가하지 않았으며 출처 검증을 완화하지 않았다. 무작위 ID·이전 revision·자연어 시각에 대한 회귀 검사도 추가했다. 이후 실제 조율과 일정 반영이 성공했다.

프롬프트는 `ko-relationship-5`다. 10호출 중 이전 버전 8회, 새 버전 2회로, 기존 개인·공유 결과를 유지하고 공동 조율부터 재개했다. 이전 32사례 평가 전체나 개인→공동 모든 단계를 새 버전으로 다시 평가한 것은 아니다. 새 버전의 증거는 92개 검사와 이번 조율 재개 흐름이며, 사람의 언어 품질 평가는 아직 하지 않았다.

입력값에 따라 접근성 이름이 바뀌던 textarea/select에 안정적인 이름을 부여했다. 실모델 응답을 다시 생성하지 않고 저장된 단계부터 검증을 이어갔다. 환경의 Turbopack worker 오류는 webpack 빌드로 해결했다.

합성 진단의 원문 파일은 gitignored `.data/`에만 있으며, 최종 서버에서는 진단 환경 변수를 해제했다. 앱 DB·세션 상태·키·인증 secret은 커밋하지 않는다.

## 다른 작업과의 경계

검증 기준 프론트는 `ef47b6a`다. 작업 중 원격 `민경민`에 이후 커밋과 최신 연동 계획이 추가된 사실을 확인했으나 이번 검증 범위에 자동 병합하지 않았다. 같은 폴더의 `STATUS.txt`, `docs/BACKEND-INTEGRATION-PLAN-2026-11-01.md`는 별도 작업 산출물로 보존한다. 기존 프론트 브랜치 및 AI 원본 브랜치는 수정하지 않는다.

현재 통합은 개인 원문을 소유자 전용으로 저장한다. 별도 최신 계획의 원문·AI 초안 비보관 정책은 이 검증본에 아직 구현되지 않았다. 따라서 최신 정책까지 반영된 완성본이나 공개 서비스 준비 완료로 간주하지 않는다.
