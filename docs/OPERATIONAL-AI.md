# 운영 AI 설정 v5

사용자 선택: 한국 시간 기준 사용자당 하루20회, 서비스 전체 하루$5 상한. 이는 설정·차단 로직 승인이다. 유료 모델 호출/실제 사용자 원문 외부 전송 승인이 아니므로 현재 `AI_MODE=operational`, `AI_LIVE_APPROVED=false`다.

## 제한 방식

`src/contracts/ai-operations.ts`에 고정된 데모 정책을 사용한다. PostgreSQL `ai_reservations`에서 각 호출 전에 원자적으로 예약한다. 기존 합성 평가용 SQLite 예산원장은 그대로 보존하며 합치거나 초기화하지 않는다.

- 사용자당 KST 날짜별20회. 서버의 인증 actor ID 기준이며 프론트 입력 ID를 권한 근거로 쓰지 않는다.
- 서비스 전체 날짜별 예약액5,000,000 microUSD. 호출당150,000 microUSD($0.15)를 보수적으로 예약하여 현재 전체 최대33회($4.95)까지 허용한다. 실제 청구액이나 정확한 실사용 요금 표시가 아니다.
- 전체 동시3개, 사용자 동시1개, 사용자 요청 간 최소60초.
- 호출 시간 제한60초, 자동 재시도0. 완료되지 않은 작업은120초 lease 후 동시성 자리만 반환한다.
- 성공/실패/취소/시간초과 모두 예약액·횟수를 유지한다. 과금 여부가 불확실한 실패를 환불 처리해 상한을 우회하지 않는다.
- 한도 초과429, 시간초과504, 취소409, 비활성/모델장애503을 안전한 안내로 반환한다. 입력 원문·초안·오류 원문을 응답 로그/원장에 담지 않는다.

원장에는 id/actor_id/day/reserved_micro_usd/started_at/lease_until/finished_at/outcome만 저장한다. 프롬프트·생성문·개인 텍스트 해시·키·전체 provider metadata는 저장하지 않는다. 원장 완료 기록이 실패하면 비용예약을 유지하고 lease 만료로 동시성을 회복하며 모델을 재호출하지 않는다.

## 활성화 전 남은 결정

일반 사용자 호출 경로는 구현했지만 외부 호출은 잠겨 있다. 운영 승인에는 실제 전송할 데이터 범위·모델·가격표 확인·허용 비용·사용자 안내가 필요하다. 현재 기존 gpt-6.1-sol/호출옵션을 유지했으며 가격표를 이번에 재확인하지 않았으므로 실제 활성화 전에 확인한다. 단순히 한도 설정을 선택했다고 이 승인이 부여된 것으로 보지 않는다.

활성화한 환경은 PostgreSQL DATABASE_URL/OPENAI_API_KEY가 필수다. 키는 secret store 또는 기존 승인된 로컬 key env파일에서 로드한다. 프로필 설정과 AI_LIVE_APPROVED가 명시되지 않으면 모델 호출을 허용하지 않는다. production에는 테스트의 전역 DB 주입이나 가짜 provider를 배포 설정으로 사용하지 않는다.

인증 세션의 getActor 계약은 유지하며, 이메일 인증 등 추가 운영 정책은 인증 변경을 통합한 뒤 전체 흐름에서 재검증한다. 공개배포/실메일/새실모델호출은 이번 완료 범위가 아니다.

## migration·복구

`migrations/postgres/002-ai-operations.sql`은 migration 실행기에 포함되며 제품/복구 스키마에 적용했다. 익명/authenticated 역할의 직접 스키마 접근은 계속 금지된다. 백업 allowlist에 원장도 포함한다. v4 백업은 빈 원장으로 읽을 수 있지만, 오래된 백업으로 복구한 뒤 라이브 AI를 켜기 전 마지막 백업 이후 사용량을 별도로 대조해야 한다. 복원 명령은 AI_LIVE_APPROVED=true인 환경에서 거부된다.

실제 PG 한도 검사는 `scripts/verify-ai-ledger-postgres.ts --verify-recovery`로 복구 스키마에서만 실행한다. 테스트 날짜2099-01-01/02와 합성 actor를 사용하며 재실행 때 기존 날짜 데이터가 있으면 거부한다. 제품의 실제 사용 예산과 섞이지 않는다. 유료 모델 호출 없이 두 독립 PG pool에서20회 한도,33번째 예약 경쟁,동시3개를 확인했다.
